# Operational Limitations & Scientific Disclaimers (`docs/limitations.md`)

While UniGuard AI delivers robust passive detection and network security monitoring for unidirectional IP traffic, real-world deployment in operational technology (OT) and air-gapped enclaves presents inherent constraints that must be understood transparently.

---

## 1. Scientific & Ethical Disclaimers

> [!IMPORTANT]
> **Observation-Based Detections:**
> All security findings, anomaly scores, and threat alerts generated by UniGuard AI are based solely on passively collected network flow metadata and configured mathematical detection models. Detection of anomalous statistical behavior does not establish malicious intent by itself. Human analyst review and contextual verification are mandatory before initiating incident response.

> [!NOTE]
> **Synthetic Benchmark Representation:**
> The pre-packaged demonstration datasets are generated locally to safely model attack characteristics without exposing production critical infrastructure to actual cyber weapons. While statistical distributions accurately reflect adversarial techniques (e.g. port sweeps, SYN floods, C2 beacon jitter), benchmark metrics (such as 99.8% accuracy) represent synthetic test evaluations and must not be characterized as "real-world validated" enterprise guarantees.

---

## 2. Inherent Unidirectional Operational Constraints

### Lack of Reverse Handshake Visibility
In unidirectional monitoring, reverse traffic (e.g. server SYN-ACK, TCP RST, or HTTP response payloads) cannot reach the sensor due to optical or physical diode enforcement:
- The sensor cannot observe server responses to verify whether a probe succeeded or failed.
- Successful TCP handshakes must be inferred from the arrival of subsequent PSH/ACK packets or progressive sequence numbers.
- Half-open scanning attempts cannot be confirmed via server RST responses unless reverse streams are tapped separately.

### Zero Active Interrogation
Because active scanning, pinging, and banner grabbing are prohibited by design to protect air-gap integrity:
- Asset roles (SERVER, CLIENT, GATEWAY, DNS) are inferred heuristics based on observed port communications and traffic directions.
- The sensor cannot query an endpoint for OS patch levels, installed software, or vulnerability status.

### Encrypted Channel Obfuscation
Adversaries employing sophisticated traffic padding (e.g. Pluggable Transports, Obfs4) or artificial jitter morphing can obscure packet size distributions. UniGuard AI addresses this through multi-signal correlation across multiple consecutive flows rather than relying on a single packet inspection.

### Software vs. Hardware Assurance
Software configuration alone cannot physically guarantee that packets cannot be transmitted. While UniGuard AI enforces passive read-only mode in code (zero socket write calls, disabled active response handlers), physical unidirectional assurance requires deployment on a certified hardware optical data diode or Rx-only physical TAP.

## 3. Recommended Future Work

1. **Kernel-Bypass Ingestion (DPDK / eBPF):** Offload packet capture from Python/Scapy to Linux eBPF / XDP or DPDK for sustained 10Gbps+ wire-speed unidirectional sniffing.
2. **Dual-Diode Correlation Enclave:** Ingest two separate, physically isolated unidirectional streams (inbound diode + outbound diode) into a central correlation node to achieve full bidirectional session reconstruction without creating a return path between enclaves.
3. **Temporal Deep Learning Sequence Models:** Incorporate lightweight Tiny-Transformer or 1D-CNN temporal sequence models for detecting highly stealthy low-frequency encrypted C2 beaconing.
4. **Standardized Syslog / CEF Push:** Forward correlated alert dossiers over an isolated SOC management interface to enterprise SIEM platforms (Splunk, Microsoft Sentinel, Wazuh).
